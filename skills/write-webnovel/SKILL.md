# 网文撰写

目标是让读者因人物正在做的事期待后续。先兑现本段承诺，再让结果产生新的欲望、冲突或机会；不能用不断延迟答案代替推进。

## 入口与任务边界

1. 确认作品、任务模式与允许修改范围：构思、续写、修订、审读。已有上下文能确定的，不重复询问。用户只要求分析时不改稿；已授权改正文时交付实际修订，不能只交建议。
2. 读取项目入口、写作规则、现版规划、相关人物和必要原文。先确认唯一事实源；历史会话用于提取偏好和决定，不直接补当前故事事实。用户本次明确修改设定时，落实修改及关联影响。
3. 新作品没有资料体系时，用简短的设定与连续性记录即可，不强制建立数据库、脚本或庞大审计体系。仅缺少会决定写作方向的关键信息时提问；其余采用可说明的假设推进。
4. 《我们宗门正在逃跑》或《逃跑》任务先读 [本书适配](references/taopao-adapter.md)，再按项目现版要求操作。其他小说跳过该参考。

## 按任务加载材料

- 构思、拆单元、写正文：读 [故事与场景方法](references/storycraft.md)。续写还要读前文实际结果和本章依赖，不能仅看细纲。
- 多章修订、重排、事实核验：读 [连续性与修订](references/continuity-and-revision.md)。先连读问题区间及其前后承接，再判断病因。
- 用户询问技能依据或要求更新方法时：读 [提炼依据](references/sources.md)。不要把参考文件全部装入每次写作上下文。

## 原始素材改编

从短篇、思想笔记或历史材料构思长篇时，读 [原始素材改编](references/source-adaptation.md)，将素材转化为人物选择与故事因果，不机械逐篇对应章节。

## 写作主链

用具体行动填写：**谁想要什么 → 主动做了什么 → 遇到谁的不同打算或什么限制 → 作出什么选择 → 得到什么可见结果 → 因此又想做什么。**

- 开篇尽早建立读者能说出口的期待：想看谁逃出去、赢一次、揭穿谁、获得什么或如何收场。宏大谜团不能代替眼前可追的事，不规定机械的字数或章数门槛。
- 主动性来自选择、准备、承担和改变结果。不能只在内心补一句“其实早有打算”。表面被迫、实际主动只是可选机制，不是所有主角的模板。
- 成长保留并改变人物的欲望：想赢、爱美、要面子、好奇、贪嘴、怕失去等应继续驱动行动。可靠不能等于无欲、寡言、永远正确。
- 配角各有想要的东西、独立手段和后果。张扬者可以张扬成功，安静者可以通过决定被记住；不要把全员改成外放，也不要让全员负责提醒主角守边界。
- 能力和合作必须有来源、范围与限制。让别人因主角做成过一件具体事而信任他；强者保留自己的目标和判断。
- 胜利留下可用成果，并给人物享用、得意、松口气或得到认可的空间。新问题可以接续，但不应惯性地把每次所得立即收走。
- 章尾从刚发生的结果生长：新选择、承诺、对手反应、关系变化或可执行机会。温暖收束也可以成立，不强制每章悬崖、危险或反转。

## 五问审读

逐项给出**正文位置或原句 → 读者可能产生的期待/感受 → 判断 → 必要时的具体改法**。这是编辑判断，不伪造读者实测。尚未写出的卡只能评估设计。

| 问题 | 判据 | 常见修订动作 |
| --- | --- | --- |
| 开篇读者具体想看什么？ | 能说出人物、眼前目标与想看的结果，不只复述世界观 | 将选择或行动前移，延后不影响理解的说明 |
| 哪些地方开始觉得重复、想停？ | 标出连续场景重复的承诺、手段和结果；换地名不算变化 | 合并同功能步骤，提前兑现，改变下一段的行动方式 |
| 记住哪个人物，因为他主动做了什么？ | 能指出只有此人的欲望、判断或能力会引发的动作及后果 | 把提醒、附和、旁观改为自主决定；允许配角拥有自己的胜利 |
| 胜利有没有让人高兴，还是立刻变成新的负担？ | 成果被使用、享受、认可或扩大选择；代价没有抹平全部所得 | 留出兑现与情绪停留，分开庆祝和下一轮压力 |
| 下一段期待是否由刚发生的事自然产生？ | 上一段的结果改变了人物下一步，而非凭空发新任务 | 用成果、失误、承诺或他人的反应触发后续 |

不要为了表格全通过，把每章都塞满笑、爽、燃、泪。审读单位按问题选：一个场景、一组连续章节、一个故事单元或全书容量。

## 从诊断到交付

1. 先列最影响阅读的少数问题，区分结构、人物因果、情绪兑现与措辞；避免只改句子掩盖事件不前进。
2. 用“现象—原文证据—改动—预期改善—受影响后文”形成可执行修订。已写正文是否可改由用户授权决定，不自行保护某个章号之前的内容。
3. 在授权范围内完成正文、连续性记录和必要规划同步。保留有效的安静场景与人物呼吸，不以删字比例为目标。
4. 重读修改段及承接段，再答五问；检查知识、能力、资源和伏笔的前后依赖。机械检查仅证明其实际覆盖的结构或一致性。
5. 达到约定修订目标且相关矛盾已解决即可结束。报告实际改动、证据和残留问题；不因“还可以更好”无限微调，不声称已保证追更、爆火或月收入。

交付以用户要的正文、方案或审读为主。用户要求执行时，不能用一份“执行建议”代替已授权工作。写作、登记、发布、部署是不同操作，不从写稿授权推导发布授权。
