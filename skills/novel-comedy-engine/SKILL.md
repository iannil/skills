# 人物驱动的喜剧事件

## 使用边界

先确认作品、分析／设计／改稿模式及授权范围；上下文已清楚时直接执行。分析请求不改正文，已授权改稿则交付实际修改。读取作品现版入口、相关规则、人物资料、目标原文及必要前后文；不把摘要当全文阅读，不把未来规划当既有事实。新作资料不足时仅追问会改变方向的关键问题，其余采用明确假设。

《我们宗门正在逃跑》（简称《逃跑》，历史别名含《我的宗门正在逃跑》）先读项目内 `books/zongmen-taopao/README.md` 与 `AGENTS.md`，按其当前流程取材、改稿与登记。其他作品沿用自己的规则，不继承该书人物、禁用设定、章号或工具要求。

这是专项能力，可独立使用；综合写作可由已有 `write-webnovel` 承接，但不要求同时加载其他技能。按当前问题选择方法，不将全套检查强塞进每章。项目事实和当前用户意图优先于本技能的案例偏好。

## 从认真想做的事开始

先找人物真正舍不得放下的小欲望：体面、认可、节省、胜负、好吃、好奇等。人物有自己的道理，笑点来自他们的办法与现实相撞。不要先写笑话再让人物失去常识来配合。

可选事件链：**小算盘奏效 → 成功引来更多需求 → 各人按自己的理解加入 → 补救改变局面并生新麻烦 → 作出选择 → 留下真实结果和余波**。升级次数服从事件，不机械套三次反转。

## 四项生成检查

1. **因人而异：**夸口、圆话、认真落实分别由不同欲望驱动；配角能发动或扩大事件，不总由一人犯错、全员纠正。
2. **世界不可替代：**身体尺度、术法、职业、资源或社会关系是否改变行动？换成普通旅行团仍原样成立时，考虑是否浪费了作品的独特条件；普通日常笑话仍可存在。
3. **补救有后果：**误会会改变承诺、分工、花费或下一步行动。若撤去笑话后剧情完全不变，判断其是否仍有关系或节奏价值，而非一律删除。
4. **结果有所得：**可出丑、可反套，也可以漂亮成功；不能每次一得意就受罚，或靠归零收入和本领制造下一轮穷困。

## 写在动作与反应里

铺垫让读者理解人物想要什么，包袱落在选择、对白、反应和后果上。动作完成后删掉重复解释“这为什么好笑”的句子，保留必要叙述与心理。不用满屏现代热词替代人物声口，不以受害、贫穷和伤病本身为取笑对象。

让不同人有不同速度与温度：安静者的认真决定也能造成强反差，不必改成嘴贫。不要让聪明人物反复忘掉已掌握的常识；失败可来自过度自信、未知条件、欲望偏差或对手反制。

## 长篇中的变化

检查同一笑法的前次使用与结果。成长后可以从被误解转向主动利用误解，从吹假话转向真话被夸大，从等人圆场转向自己承担；不是每次恢复原状。

核心喜剧事件可跨章，但每阶段需改变局面，不能只加更多围观者和同义包袱。伤痛、告别与信任破裂若需要情绪停留，允许喜剧暂退；不要用尾句笑话冲掉刚付的代价。

交付给出人物欲望、事件触发、升级动作、具体包袱、实际结果与后续影响；若用户要正文，写成场景而非只交机制说明。评价用“预期形成何种反差”的编辑判断，不宣称必定让读者笑。

## 交付与完成

设计任务给出可演出的方案；审读给出“具体位置或原句—问题机制—影响—必要改法”；执行任务完成授权改稿并复读直接承接处，同步项目要求的记录。没有充分材料时注明审读范围，不宣称全书已核验。约定问题解决且关联矛盾已处理即可结束，避免无限微调。

分别说明设计成立、正文已兑现、工具检查通过与真实读者反馈。编辑判断不能冒充留存、爆火或收入证据。写稿不自动授权发布、提交或部署。
