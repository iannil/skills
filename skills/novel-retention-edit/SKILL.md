# 连载节奏与追读修订

## 使用边界

先确认作品、分析／设计／改稿模式及授权范围；上下文已清楚时直接执行。分析请求不改正文，已授权改稿则交付实际修改。读取作品现版入口、相关规则、人物资料、目标原文及必要前后文；不把摘要当全文阅读，不把未来规划当既有事实。新作资料不足时仅追问会改变方向的关键问题，其余采用明确假设。

《我们宗门正在逃跑》（简称《逃跑》，历史别名含《我的宗门正在逃跑》）先读项目内 `books/zongmen-taopao/README.md` 与 `AGENTS.md`，按其当前流程取材、改稿与登记。其他作品沿用自己的规则，不继承该书人物、禁用设定、章号或工具要求。

这是专项能力，可独立使用；综合写作可由已有 `write-webnovel` 承接，但不要求同时加载其他技能。按当前问题选择方法，不将全套检查强塞进每章。项目事实和当前用户意图优先于本技能的案例偏好。

## 先找读者正在等的结果

连读用户指定区间与直接承接，记录期待何时建立、期间每场改变什么、何时实际兑现。分别看连续阅读与按章更新：章数减少可能缩短更新等待，但不等于删掉同等阅读篇幅。未知字数和未读章节不估作已核验数据。

用五问定位少数最影响阅读的问题：

1. 开篇具体想看谁做成什么？宏大世界观和远期谜底不能替代眼前行动。
2. 哪些场景重复了同一承诺、手段或结果？过程合理仍可能重复。
3. 哪个人因主动选择而被记住？主角是否只做协调与善后？
4. 成功是否得到使用、享受或新选择，还是立即被收走？
5. 下一步是否由刚发生的结果触发？去掉末句神秘预告后，是否仍有可追的事？

## 按病因选择修改层级

| 层级 | 识别依据 | 可选改法 |
| --- | --- | --- |
| 句子 | 相同信息反复解释 | 删重复，保留声口和必要条件 |
| 场景 | 多场核验同一条件而不改变决定 | 并场、省略交接、让必要核验伴随行动 |
| 事件 | 换地方仍重复求助、准备、验收 | 改变对手策略、人物选择或解局方式 |
| 连载 | 目标明确却多章没有所得 | 前移行动，安排有独立价值的阶段结果，重设章界 |
| 全书 | 单元为字数配额延长 | 按独特矛盾重新分配容量 |

先列应保留的高潮、关系变化、必要条件和情绪停留，再提出最小有效修改。删字率不是目标；章节合并、段落压缩与关键结果前移分别说明。不能靠把已发生事件改称“铺垫”掩盖倒序矛盾。

区分无变化与低强度：告别、吃饭、病客、夜谈可兑现亲近、自由与生活改变，不强加笑点、危机或悬崖。分章优先完成一个可感知变化；具体期待可来自好奇、想见成功、关系牵挂或局势担忧。

## 修订后验证

再读改动段和直接后果，检查原承诺是否仍成立、结果是否确实更早或更充分、跳过步骤后因果是否可懂、安静人物和情绪是否被削平。遇到具体依赖问题才扩大范围。

输出可用“范围／期待建立点／现有兑现点／重复功能／修改动作／保护项／后续影响”表；无须给每章机械评分。若有真实试读，保留读者原始停读位置与原因，和编辑推断分列。

## 交付与完成

设计任务给出可演出的方案；审读给出“具体位置或原句—问题机制—影响—必要改法”；执行任务完成授权改稿并复读直接承接处，同步项目要求的记录。没有充分材料时注明审读范围，不宣称全书已核验。约定问题解决且关联矛盾已处理即可结束，避免无限微调。

分别说明设计成立、正文已兑现、工具检查通过与真实读者反馈。编辑判断不能冒充留存、爆火或收入证据。写稿不自动授权发布、提交或部署。
