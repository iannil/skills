# 检测协议（less-ai-tone 第一步）

本文定义检测阶段做什么、不改什么。改写规则见 [SKILL.md](./SKILL.md)。

## 为什么先检测再改写

1. 许多 AI 味是**分布特征**（句长均匀、用词不敢重复），单点改坏文章；应整篇决策。
2. 先给有指标、例句和改法的报告，等用户回复再动手，防止把非 AI 味特征一并清掉。

## 三层分工

| 层 | 管什么 | 谁 |
|---|---|---|
| 脚本层 | 正则命中、标点密度、结构 CV、mtld | `scripts/detect.py` |
| 语义层 | 同义重命名、衔接连环、冒号分类、同构三连 | 会话模型 + [semantic-criteria.md](./references/semantic-criteria.md) |
| 人审层 | 比喻贴切度、暗喻、拟人 | 用户 |

## 运行

```bash
python3 scripts/detect.py <文件或目录> [--max-hits 5] [--json]
python3 scripts/detect.py <文件> --candidates --out 候选.json
python3 scripts/report.py 原文 改后 before.json after.json \
  [--semantic 判读后.json] --out 报告.md
```

## 分级

| 级 | 含义 | 策略 |
|---|---|---|
| **A** | 固定句式/标点，语义风险低 | 复核后建议；用户回复后改 |
| **B** | 需重组句式或换说法 | 逐条筛选；用户回复后改 |
| **C** | 结构/节奏分布 | 默认不改 |
| **H** | 贴切度难判 | 默认保留；用户要求再列 |
| **X** | 实测非 AI 味 | 永不改，仅防误改 |
| **F** | 分模型指纹 | 可定位且安全则默认拟改；不推断作者模型 |

分级看**改动风险**，不看「感觉有多强」。

## X / F 口径摘要

- 序数词小标题、「这意味着」、空转句引列表、概括替代 → **X**
- 破折号在配对中分模型分化 → **F**；密度 >2/千字优先，低密度仍可逐处检查

## 报告怎么读

脚本输出是候选数据。模型复核后，改前报告须把「本篇命中 → 研究参照 → 例句 → 改法」讲清。不得静默删除候选；误报与阴性判读也要留数量和理由。研究语料显著 ≠ 本文作者是 AI。

## 留给人的判断

- 比喻是否贴切；三个案例是否凑数；「参差」是自然还是机械长短交替
- 段首零主语评论：不再检测计分
