# 去 AI 味（less-ai-tone）

识别并改写中文成稿里的 AI 写作痕迹。顺序固定：**先检测 → 语义层判读 → 交付改前报告并等待回复 → 再改写 → 复测对比**。用户回复「按建议改」即可继续；也可一句话调整范围。收到回复前不得改正文。

规则口径来自公开去 AI 味实测（约 629 篇对照 + 270 对同题配对）。本仓库正文与脚本为原创改写，见 [ATTRIBUTION.md](./ATTRIBUTION.md)。

**默认定位（MIT）**：宿主长文成稿门禁可默认使用本包；与原版同族工作流，目标为效果持平（见 `evals/orig-vs-rew/`）。研究长文/案例包仍可参考原版 skill，本包不搬运 BY-NC 资料。

检测分三层：

- **脚本层**：`scripts/detect.py` 统计正则/标点/结构指标
- **语义层**：按 [references/semantic-criteria.md](./references/semantic-criteria.md) 对候选逐条封闭判读
- **人审层**：比喻贴切度、暗喻、拟人化喻体——默认保留，模型不假装能判

分级含义见 [DETECT.md](./DETECT.md)。

## 工作流

### 1. 脚本检测

```bash
python3 scripts/detect.py <文件或目录> [--max-hits 5] [--json]
```

改前务必带 `--json` 存档，供第 4 步对比。

### 1.5 语义层候选

单篇必跑；目录批量可选：

```bash
python3 scripts/detect.py <文件> --candidates --out /tmp/candidates.json
```

对四类候选（同义重命名段 / 段间衔接 / 冒号句 / 三连同构）按语义判据给 `label` / `confidence` / `reason`，写回 JSON。纪律：只按判据、每条独立、拿不准选兜底、禁止自造标签。再汇总：重命名次/段、最长连环、结论冒号占比、高度同构三连数。

### 2. 改前报告，然后停下

交付专业可读的改前报告后结束本轮。至少包含：

1. **方法与口径**：脚本量了什么、语义层判了什么；字数/段数/候选数。区分「研究语料显著」与「本篇单次命中」；未做单篇显著性检验不得宣称本文统计显著，也不得断言作者是 AI。
2. **指标与去向**：表列第一层跨模型指标与第二层指纹。可定位项写清原始命中、有效命中、拟改、保留；分布指标只报实测值。命中清单不可静默删项。
3. **例句与改法**：每个拟处理指标摘 1–2 处原句并定位，说明机制与可执行改法。此时不交付改后全文。
4. **排除与范围**：保留/排除的数量与理由；汇总拟改范围后，只请用户对整套建议回复「按建议改」或提出调整。

有效且可定位的 A/B/语义/F 局部命中，默认拟改；「保留」须举证（修辞、引文、术语、风格不可替换）。C 级不假装成某句错误；H 级交人审。

### 3. 改写

只改用户接受或调整后纳入的项。每处记录「原文 → 改后 + 规则编号」。

#### 效果持平执行清单（改写时必过）

用于避免「检出了但改不干净」。在信息守恒前提下，对已纳入方案的项：

1. **弱翻案也要清**：不仅「不是 A 而是 B」，也包括「不是好奇那么简单」「不是开票本身，而是…」「不是在买 X，是在买 Y」等先立误解再收束的支架；以及「与其…不如/宁可…」对举。改成正面陈述，反面信息若有独立价值则另句保留。
2. **装饰性破折号默认改**：密度 >2/千字时，悬置结论、延长停顿的 `——` 优先改句号/逗号；仅当插入解释/语气功能不可替换时保留并举证。
3. **连续分号可拆则拆**：一句内多个 `；` 叠层时拆成句号；确有并列层级才保留。
4. **顿号并列**：说明段里的同构三项尽量打散或概括；**法规/配置/状态枚举/字段清单**可保留（须在报告写明）。
5. **改后闸门**：复测时，拟改的翻案腔/提示语冒号/起手式/装饰破折号应为 0，或逐条保留举证；禁止「大体干净就停」。

### 4. 复测与对比报告

```bash
python3 scripts/detect.py 改后.md --json > /tmp/after.json
python3 scripts/report.py 原文.md 改后.md /tmp/before.json /tmp/after.json \
  --semantic /tmp/candidates_labeled.json --out 去AI味报告.md
```

默认 Markdown；要网页版加 `--format html`。复测应核对拟改项是否完成；C 级数字只解读，不追求把句长 CV 机械拉高。

## 改写原则

1. **最小改动**：只改解决该命中所必需的部分。
2. **信息守恒**：观点、事实、限定词、数字、引语、来源完整保留。
3. **不制造参差**：不为「像人」强行打乱句长/段长。
4. **结构不动**：标题层级、段落顺序、列表、表格、引用、代码块位置保留；小标题编号不改。
5. **有风格参考先读参考**：冲突时以作者风格文档为准。
6. **改完自查**：每处能对应规则编号；实词有出处；拟改 A/B 清零或有说明；C 无大幅摆动。

## 不改的情况

- 对话体、口语体；问句与设问小标题
- 文学性排比/比喻（按原风格）；学术/公文不必强加「我/你」
- 代码块、外语、引文
- **X 级**：序数词小标题、「这意味着」复述、空转句引列表、概括替代（同段有数也不改）——永不改

## 改写规则（优先级）

### 1. 翻案腔

「不是…而是…」「看似…实则…」等先立误解再推翻。也包括弱翻案支架（如「不是好奇那么简单」「不是在买 X，是在买 Y」）。改法：正面下判断；若反面信息仍有用，另句保留，不要靠对举撑结构。

### 2. 提示语冒号

「一句话总结：」「核心是：」等。删空提示，或前半句承接时只换标点。空转句引列表属 X，不改。

### 3. 起手式

「说白了」「先说结论」——删掉直接给判断。

### 4. 翻译腔（四种）

过长前置定语；「当…时」前置；前置话题壳；句首「然而/因此/此外」路标。不改「这意味着」式复述（X）。

### 5. 顿号罗列过密

一分句内两项以上顿号、三项以上并列。能概括就概括；否则打破同构。法规/配置清单与 Markdown 列表内部不改。

### 6. 相邻句结构同款

相邻句同一骨架。打散其中一句；不动段序、不删信息。

### 7. 拟人化喻体（人审）

默认保留。用户要求时改成工具/系统实际做什么。

### F. 指纹

破折号/分号/引号是模型偏好，不推断本文作者模型。破折号密度 >2/千字优先；可安全改的局部默认拟改，保留须说明功能。引号偏少不构成补引号理由。

### 8. 破折号

优先处理高密度文本；改成完整句或逗号/句号，不损失关系。

### 9. 段首零主语评论

不再扫描、不计分、不进报告。正文遇到悬空评论可补指词，但不作为检测项。

### 10–13. 语义层

10. 同义重命名：段内同一概念换实义说法 → 统一回原名词。  
11. 衔接连环：明确承接 ≥6 → 选 1–2 个接口改成自然跳跃。  
12. 结论提示冒号：冒号前独立结论、后展开 → 同规则 2。  
13. 高度同构三连：骨架逐字复刻 → 拆掉其中一句骨架，不删内容。

## 嵌入其他 skill

长文撰写类 skill 在交付连续成稿前，加载本包（路径优先 `./less-ai-tone/`，否则本权威包）并执行完整工作流。

- **门槛**：连续中文散文约 ≥800 汉字才默认跑；大纲、纯表格、纯代码、术语对照可跳过并注明。
- **冲突**：宿主 skill 的体裁约束优先（小说声口、工程模板清单引导语、引文/代码）。
- **诊断-only / 用户跳过**：只报告或不跑，不改写。
- **体裁力度**：非虚构/报告全流程；小说全流程但文学排比与有意反复默认保留；工程蓝图只处理连续说明段，模板结构不动。

## 最终验收

- 改前报告含指标、参照、例句、改法与排除项，并已等待用户回复
- 语义判读只用封闭标签；每处改动对应规则编号
- 最小改动；信息守恒；结构保留；X 级未误删
- 复测对比报告已交付；拟改 A/B/F 主信号清零或有说明；C 无大幅摆动
- 效果持平执行清单已逐项过：弱翻案、装饰破折号、可拆分号、说明段顿号未漏改
