# Agent 学习效果评测

先明确待检验的主张：资产能保存、能被检索、能被正确使用、能提高任务结果，是四个不同层次。没有收益证据时可以交付有效的评测和阴性结果，不能以资产数或成功示例代替效果。

## 固定比较对象

记录运行时、模型及参数、提示、工具、预算、环境和资产版本。明确学习阶段与评测阶段是否允许修改资产；通常冻结评测资产，每次任务使用独立副本，检查内容指纹，防止跨组污染。在线持续学习是另一种实验，不能混用冻结评测的结论。

根据主张选择必要对照：空资产基线、学习资产、匹配规模的无关资产；只验证简单复用时不强制全组，验证“学到的内容而非额外上下文带来收益”时需要无关资产或等效消融。记录未控制的差异。

## 先校准，再封存

用开发题检查可解性、验收器正确性、任务难度与预算。目标难度范围在看学习组结果前约定，过易或过难按任务族调整，不为了让学习组获胜挑题。

将训练、开发和保留评测题隔离；新项目名称或随机数变化不自动构成新任务。核对解法、模板和答案是否泄漏。修题或修改验收器后生成新版本，不把旧结果混入同一统计。

实际执行前按 [实验协议与结果判定](references/evaluation-protocol.md) 写下比较、样本安排、主要指标、失效条件、成本上限及停止规则。设计请求停在方案；真实调用只在已有授权与预算内执行。

## 运行与判定

结果尽量由独立可执行的验收器、文件断言或外部结果确认，避免让同一个 Agent 自评成功。开放题用事前定义的量表并隐藏组别，记录评分不确定性。

配对相同任务条件，随机或交错组别顺序。保存每次尝试、退出状态、错误类别、请求量、Token、费用和耗时；重试记入成本，不只留下成功运行。无凭据或隐私原文进入公开报告。

区分任务失败、工具或环境失败、输出截断、冻结协议违规与验收器错误。协议无效的数据不能悄悄计成成功，也不能直接用来证明能力退化。说明有效样本分母与排除理由。

分别报告任务成功、旧能力保持、无关能力退化、资源成本与资产选择正确性。样本不足、上限效应或协议缺陷时结论为“不足以判断”，而非“没有收益”。失败后调整学习方法需用新版本重新评估。

## 交付

交付可复现协议、题包与资产版本、逐次结果入口、分组统计、异常及结论边界。已实现评测器、已完成校准、已测得收益分别说明；不得用离线回归通过替代真实模型收益验证。
