# SEO / GEO 循证优化

把真实需求、发现与索引、内容证据、准确呈现和用户行动连成可验证的工作链。SEO 与 GEO 共用基础，但分别衡量搜索展示、品牌提及、本站引用、推荐与业务结果。

## 选择当前任务

从用户请求与已有材料确定范围，不强制每次执行完整审计。优先使用已给出的站点、代码、报告、目标和授权；缺少关键信息时先完成独立可做的部分，再询问会改变决策的问题。

| 用户需要 | 本轮交付 | 按需读取 |
|---|---|---|
| 最新实践、规则或方法研究 | 带来源、核验日期、适用范围的结论；已知与待验证分开 | [证据与平台](references/evidence-and-platforms.md) |
| 诊断网站或制定策略 | 阻塞环节、证据、P0–P3 优先级、可验证下一步 | [工作流程](references/workflow.md)、[交付模板](references/templates.md) |
| 写作、改稿、规划内容 | 对应真实任务的内容或简报，附证据缺口和维护条件 | 工作流程中的内容部分、交付模板 |
| 实施优化 | 在现有授权内完成改动与相应验证，区分本地/线上状态 | 工作流程；涉及平台配置再读证据与平台 |
| 统计 AI 引用或判断效果 | 固定口径的分子/分母、原始记录、限制与下一轮假设 | [测量协议](references/measurement.md) |

只读取本轮需要的参考文件。任务横跨多种模式时组合使用，不把参考清单变成必须全部执行的任务。

## 核心工作法

1. **定义结果。** 明确受众、任务、地区/语言、目标平台与成功行为。分清业务目标和本轮可验收交付。
2. **定位阻塞。** 沿“访问 → 发现/索引 → 检索匹配 → 展示/引用 → 准确性 → 用户行动”寻找证据。未知阶段保留未知，不能以后一阶段的建议替代前一阶段的问题。
3. **分级依据。** 区分 A 平台事实、B 条件性研究、C 方法建议、U 未知。官方功能说明不是收益实验，相关性不是因果。
4. **选最有价值的改动。** 先修真实阻塞与事实错误，再补核心任务和独特证据。依业务重要性、需求依据、独有价值和维护成本排序，不套固定关键词难度或发布频率。
5. **完成授权内工作。** 研究就交付研究；要求实施时推进实际实施，遵循目标项目的工作流与验证命令。新账号、付费、发布、爬虫权限或外联不由“做 GEO”自动授权，也不为已授权动作重复确认。
6. **核验并交接。** 报告实际改动/观察、证据位置、验证范围、未覆盖部分与下一决策。技术通过、收录、引用和业务改善各有自己的验收证据。

## 保持的判断边界

- 当前平台功能、bot、政策和指标易变：优先复用本轮已核验资料；否则查相关官方页面。参考文件中的 2026-10-09 信息是研究快照，不可自动称为今天的状态。无法联网时注明未复核，并继续可完成的内容/数据工作。
- 不保证排名、引用、转化或见效天数；不把自定义得分当算法权重、引用概率或跨语言质量分。
- 不把 FAQ 数量、固定字数、年份标题、Schema 或 llms.txt 当普适成功条件。根据用户任务与具体消费者决定是否采用。
- 不虚构作者、资质、客户、测试、统计、报价、评价或更新时间。示例明确标注；重要事实应有来源、时间、条件和必要的数值口径。
- 搜索抓取、训练抓取和用户即时访问分开处理；索引通知收到不等于收录。只修改用户授权的访问范围。
- 已收录不保证被检索；被提及不等于官网被引用；引用不等于推荐，链接存在不等于支持对应主张。
- 批量内容必须有逐页独有任务、数据或功能；真实独立声誉不能用买链接、伪装用户或重复宣传替代。
- 不挑最好的一次 AI 回答作效果证据，不删去无引用样本提高分数，不将未测或失败填成零表现。

## 输出完成条件

按请求选用模板，不必生成固定篇幅或全部表格。至少让用户知道：结论是什么、根据什么、做了什么或建议先做什么、如何验证、还有什么未知。平台与统计结论就近给出来源或原始数据位置。
