# 测量与效果判断协议

用于解读站长数据、统计 AI 可见度、设计固定题集或评估改动效果。兼容用户已有表结构；先建立字段映射，不为采用本协议强行迁移既有数据。

## 对齐四类数据

1. 技术健康：访问、索引资格、实际索引、规范 URL、现场性能。
2. 搜索表现：展示、点击、CTR、查询/页面、品牌/非品牌、地区与设备。
3. AI 呈现：平台报告的展示/引用；固定题集的品牌提及、本站引用、推荐与主张支持。
4. 用户结果：任务完成、合格线索、激活、购买、留存与成本。

平台报告、自建题集与分析工具分开，不拼成全网 AI 市占率。当前字段先查 [平台资料](evidence-and-platforms.md)。尤其检查报告包含关系、数据缺失、时区与聚合层级。没有同范围点击，不能用全站点击除 AI 展示生成“AI CTR”。

## 采样与证据保存

问题来自真实任务；品牌题用于身份/事实，非品牌题用于自然发现；探索题与正式比较题分开。按目标、成本和预期变化设计数量与重复次数，不把“30题×2平台×3次”当标准。

事先固定问题、语言、地区、产品入口/API、模式、会话条件、采样周期和统计规则。模型不可见填 unknown；“搜索设置开启”与“观察到搜索过程”是两个字段。

记录首个完整结果、实际时间、原文和完整来源。不能重问直到出现满意回答；技术重试保留失败与重试关系。不要把 API 调用等同消费者产品界面。

## 推荐数据模型

已有协议可以用别名映射，保留原始记录。

**回答表：一行一个预定运行槽位的选定结果。**

```text
sample_id, question_id, question_text, intent, branded,
language, region, platform, interface_or_api, displayed_model, mode,
search_setting, search_observed, run_id, captured_at_with_timezone,
session_condition, status, response_kind, evidence_path,
brand_mentioned, brand_recommended, task_satisfied, reviewer_notes
```

- sample_id 唯一，包含题目、平台、语言、条件和重复序号的身份；日期窗口变化分开建批次。
- status：completed / technical_error / not_run。completed 指技术完成，不保证任务有解答。
- response_kind 可记 substantive / clarification / refusal / other。澄清、拒答和无引用回答不能为了提高指标临时排除。
- 缺失布尔值用 null/unknown，不强填 false；未标注与真实无出现不同。
- 多次技术尝试另存 attempt 记录；一个运行槽位不要因为多次尝试重复增加计划分母。

**引用表：一行一个来源，关联 sample_id。**

```text
sample_id, citation_id, raw_url, resolved_url_if_checked,
hostname, source_class, claim_id_if_checked,
support_status, evidence_path, reviewer_notes
```

- source_class：预先约定的自有域名、自有外部资料（如仓库）、第三方；不能把整个 github.com 算官网。
- 按解析后的真实 hostname 与明确允许域匹配；是否包含子域事先约定。不要按 URL 包含品牌字符串判断，排除 `brand.example.evil.test` 之类误匹配。
- 同个回答引用本站三次，本站引用命中仍只算一次。
- 支持性审阅的单位是“回答中的主张及其对应来源”，必要时另建主张表；未访问原文保持未核验。来源可用不等于支持主张。

## 分母与缺失值

分平台、语言、地区、模式、品牌题属性与时间窗口统计。仅在口径一致且有明确加权方法时合并。

| 指标 | 分子 / 分母 |
|---|---|
| 样本完成率 | completed 的预定运行槽位 / 计划槽位 |
| 品牌提及率 | 正确识别目标品牌的 completed 回答 / completed 回答 |
| 本站引用率 | 至少一条自有域名引用的 completed 回答 / completed 回答 |
| 推荐率 | 将品牌作为适用选择的回答 / 事先约定选择类问题的 completed 回答 |
| 主张支持率 | 获来源实质支持的已核查主张 / 已核查主张 |
| 核查覆盖率 | 已核查主张 / 计划核查主张 |

technical_error 与 not_run 不进入已完成回答的可见度分母，但必须展示完成率与失败数。无引用的 completed 计为无引用。零分母报告数据不足，不给 0% 支持率。

若 completed 中部分回答还未标注，不用缺失值伪装确定率：补标注，或只报告“已标注子集 x/y + 标注覆盖率”。已有口径排除澄清/拒答时，保留该口径及排除数量，并说明与本协议的差异，不能静默重算成更好看结果。

品牌身份人工抽查，避免同名误识别；提及、正面推荐与负面举例分开。第三方引用事实也需检查，不能只核查有利来源。

报告同时给分子、分母、绝对数量、比例、变化百分点和样本条件。重复题的多次回答通常相关；统计区间按问题簇/页面等合适单位处理，不虚增独立样本量。

## 效果验证

- 在改动前固定目标指标、原始页/题集、数据窗口和预期作用环节。
- 有条件时随机分配相近页面/问题簇到实验和对照；无法随机时明确是观察比较。
- 一轮聚焦可解释的改动，保留版本、上线时间和观察到重新抓取的时间。
- 比较等长完整窗口；记录星期构成、季节、推广、模型更新和竞争内容。前后各28天可以是起点，不能当见效保证。
- 同时比较实验/对照的前后变化；低样本、同时多改动或条件不一致时，缩小结论到“观察到关联”或“数据不足”。

引用增加而收入不变时，检查意图与落地价值，而非立即宣布成功或失败。被正确提及但无链接也可能有价值，需其他证据，不能强行归因。

## 来源归因

仅将已识别的 AI referrer/UTM 归为对应入口；机器人请求不计用户访问。保留实际落地页和转化口径；Direct 不全算 AI，Google organic 不全算 AI。自报来源和辅助转化用于补充，不能和直接归因简单累加。

## 简短报告格式

```text
观察范围与时间：
题集/页面/平台条件：
计划 / 完成 / 失败 / 未运行：
已标注覆盖与核查覆盖：
品牌提及 x/y；本站引用 x/y；推荐 x/y：
主张支持 x/y（零分母写数据不足）：
官网 / 自有外部资料 / 第三方分别观察：
与基线是否同口径；变化与不确定性：
业务结果及归因限制：
原始证据；下一验证：
```
