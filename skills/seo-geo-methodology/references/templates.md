# 可裁剪的交付模板

用于准备诊断、内容和实施交付。只采用与任务相关的字段；未知标记待核验，教学数据标记示例，不为填满表格制造事实。

## 诊断与改进台账

| 页面/问题 | 用户任务 | 所处环节 | 实际证据 | 状态/缺口 | 改进动作 | 优先级及理由 | 如何验证 | 责任/触发条件 |
|---|---|---|---|---|---|---|---|---|

状态区分观察事实、推断、待验证。验证要对应问题：例如“页面可访问”与“实际收录”分开验收，不能以 Schema 检查代替内容有效。

## 证据卡

```text
主张与证据类别（A/B/C/U）：
适用产品、版本、地区、场景、前提：
原始来源或测试记录：
指标、单位、分母、样本、周期与排除条件：
发布/更新时间与本次核验时间：
证据能支持什么；不能支持什么：
公开承接页：
维护人及重查触发条件：
```

## 内容简报

```text
目标受众 / 地区 / 语言：
页面任务与完成后的行动：
真实需求依据；候选问法：
读者已知条件：
核心回答及适用范围：
独有数据 / 工具 / 经验 / 分析：
关键主张 → 证据：
步骤 / 比较维度 / 反例 / 局限：
与既有页面分工；是否应合并而非新建：
相关内链与原始出处：
作者 / 复核 / 实质更新时间：
成功指标 / 维护触发：
```

## 实施任务

```text
目标与阻塞证据：
现有授权与本轮交付范围：
输入、依赖与前置条件：
最小有用改动：
预计成本 / 维护负担 / 优先级理由：
需要保留的既有契约与材料：
本地验证；若已授权上线则验证正式结果：
什么结果触发修订或停止：
状态、证据位置与下一步：
```

## 90 天节奏示例

仅作组织起点，按业务周期、样本量与平台变化调整；不是效果承诺，也不表示已创建自动化。

| 阶段 | 主要交付 |
|---|---|
| 第1–14天 | 目标、问题地图、核心URL、阻塞项与原始基线 |
| 第15–30天 | P0修复、少量核心任务页、独有证据与验证记录 |
| 第31–60天 | 事实维护、一次有对照的内容实验、真实站外证据 |
| 第61–90天 | 完整窗口比较、准确性/业务检查、保留或调整清单 |

## 完成前核对

- 目标人群和任务明确，页面有独立价值。
- 可访问、可索引资格、实际索引和实际引用分别取得证据或标未知。
- 事实、版本、日期、语言、规范URL和结构化字段一致。
- 案例/数据来源可追溯，无以示例充当真实成果。
- 文章与功能可服务用户，没有硬凑格式数量。
- 平台数据、自建样本、用户访问和业务结果分开；失败、缺失、分母清楚。
- 已完成与建议/计划分开；变化日志和验证局限足够他人复查。
