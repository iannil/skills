# 按阻塞环节执行

用于网站诊断、实施规划和内容改进。下面八项是工作覆盖面，不是每轮强制执行顺序；只展开本轮相关环节。涉及平台当前要求，按 [证据与平台](evidence-and-platforms.md) 核对。

## 1. 需求与业务

从真实客服/销售、站内搜索、搜索查询、用户研究提取任务；关键词工具和 AI 生成问法作为候选。没有搜索量估计不等于没有需求。

建立“受众 × 问题 × 阶段 × 地区/语言 × 承接页 × 成功行为”。阶段可分认知、操作、比较、交易和使用。不要默认任何业务都应先做成交词：新品类和公共知识可能首先需要解释与任务价值。

选题考察业务重要性、需求依据、可提供的独特证据、制作及维护成本。DR/DA/KD 等工具估计不能作为准入门槛。

## 2. 访问、发现与索引

选取核心页面和典型模板检查，范围随任务和风险扩展。

- 核对 HTTP、TLS、重定向、真实正文、软 404、登录与 CDN/WAF；浏览器可访问不能替代目标爬虫可读取。
- 检查关键内容的实际 HTML/渲染结果。JavaScript 不能一概判定不可索引；服务端输出可作为降低复杂度的工程选择。
- 重要页面有可抓取内链；sitemap 与有效规范 URL 一致。不要把提交回执当索引状态。
- 分别核对 robots、noindex、canonical 的作用。robots 不提供隐私认证；阻止抓取也可能使 noindex 无法读取。
- 按搜索、训练、用户请求区分 bot，依据官方机制验证身份。单独建 robots 分组时检查规则是否仍覆盖所需路径，不假定通配组自动继承。
- 检查实际访问和索引状态；缺后台或日志时，报告“资格可检查，实际状态未知”，不推断无收录。

## 3. 架构、语言与实体

按任务而非每个同义词拆页；概览连接子问题、操作与证据。只有受众、任务或所需内容不同才值得新建独立页。

规范 URL、重定向、内链与 sitemap 保持一致。canonical 是信号，不能证明平台选择了同一 URL。多语言正文、hreflang 双向关系与同语言 canonical 对齐；不要把全部翻译页规范到英文首页。

品牌名称、简称、所属关系、维护者、版本与公开入口使用一致事实源。只有身份关系可核验时才补关系字段，不推测相近名称就是同一实体。

Schema 类型匹配可见主内容；不造价格、评价或身份。通过检查器不等于获得富结果或 AI 引用。

## 4. 可复核证据

优先原始测试、操作过程、数据、工具、失败记录和专业分析。每项重要主张记录来源、适用场景、时间及局限；数字补指标定义、单位、分母、样本与周期。

用 [证据卡](templates.md) 管理事实和复查触发条件。引用官方声明与独立实测分开：文档写支持但未实测，就如实写明。不要为“证据密度”硬凑数字、引语或论文。

## 5. 内容生产与维护

先明确读者要做出的判断或行动，再写核心回答、条件、证据、操作和下一步。格式按任务选择，无固定字数、FAQ 数、段落长度或内链密度。

| 内容 | 重点 | 避免 |
|---|---|---|
| 产品/服务 | 人群、能力、边界、使用路径与价格条件 | 只有口号或未核实承诺 |
| 对比/选型 | 相同维度、来源、版本/日期、各自适用场景 | 无证据地把自己排第一 |
| 教程/文档 | 前提、步骤、预期结果、排错 | 无法复现的示例 |
| 案例/研究 | 方法、样本、原始记录、局限 | 示例伪装客户、相关性冒充因果 |
| 分类/目录 | 有用筛选、完整条目信息、到达目标路径 | 空分类与重复标签页 |
| 工具 | 实际可用、输入输出说明、限制 | 功能不可用却借标题引流 |

标题准确表达价值；年份只在确有时效意义时采用。更新时间对应实质改动。FAQ、表格和摘要应解决读者问题；llms.txt 等辅助格式要有明确消费者或可检验假设。

程序化页面先验证逐页差异、数据质量、独立使用价值和维护能力，再扩展规模。对已有页面，按证据决定保留、更新、合并、重定向或停止投入，不按机械年龄删除。

## 6. 真实站外证据

根据目标受众与实际引用来源选择渠道。研究、工具、开源成果、真实案例和专业贡献应便于他人核验；第三方提及与本站引用分别记录。

不要把提及与可见度的相关性变成“刷提及有效”的因果结论。商业合作与付费链接按相关要求披露；不伪装用户、买排名链接或制作虚假评测。用户未要求外联时可准备材料，不代发消息。

## 7. 用户行动与体验

给用户合理的到站价值：运行工具、下载原始材料、完成操作、按条件筛选、使用产品或获得服务。CTA 点击、真正完成任务与合格转化分开。

检查移动端、关键路径、输入错误、价格条件、加载与稳定性。现场用户指标与实验室分数分别报告，缺现场样本不填达标。

## 8. 观察与修订

用 [测量协议](measurement.md) 对齐数据，再解释趋势。每轮只做有证据支撑的保留/修订/扩展/停止决策；没有数据时指出需要的观察，不声称改善。

## 排序与业务适配

| 优先级 | 工作 |
|---|---|
| P0 | 阻断访问/索引、事实错误、功能失败或测量无法使用 |
| P1 | 核心任务页、独特证据、内部导航和行动路径 |
| P2 | 问题覆盖、真实站外证据、平台针对性实验 |
| P3 | 有明确用途的辅助格式、边缘长尾或更多平台 |

优先级随业务、成本和证据调整。按类型调整重点：

- B2B/SaaS：场景、集成、迁移和实施证据；看合格线索与激活。
- 电商：商品事实、变体、库存、价格、配送/退货与平台数据源一致；看有效订单。
- 本地服务：真实地点、营业时间、服务范围、案例与商家资料；避免无独立价值的城市门页。
- 开源/开发工具：版本、兼容性、可运行文档与排错；看成功安装和任务完成。
- 知识/教育：独特解释、原始资料、工具与持续更新；看学习任务和回访。
- 高影响主题：增加合适的专业复核、适用边界和更正机制，格式不能代替专业事实。

中文、繁体中文、海外中文和英文分别建立需求与入口矩阵。不要推定百度、豆包、元宝、DeepSeek、Kimi 等共用索引或权重；缺平台证据时采用通用流程并明确机制未知。
